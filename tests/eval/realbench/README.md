# realbench：真实数据多领域基准

这个基准用来衡量 System 1 式记忆层的两件事：**能否在对的情境里想起对的知识**，以及**能否越用越会认**。
记忆、情境、标注全部来自公开的真实数据，不含任何 LLM 生成的内容。重点放在**高级模型自己不知道、需要外挂或提醒**的知识上。

2026-10-15 审计修正了救援分支的 miss 归因：`real_api_lex` 旧日志中 58 条 `rerank_dropped` 有 49 条已经被 Jev 救援池判断。
修正后的逐条目标记忆统计为：命中 345、未召回 170、选择未入选 148、精排后也未得到救援判断机会 9。召回率不变；改变的是失败环节的解释。
`tests/eval/hardbench/audit.py` 从保留的原始日志复算这些数字；后续实时评测的 `metrics.attribute_miss` 已修正。

用已缓存的任务、冻结系统注入和正确记忆做三臂诊断，无需重跑检索：

```bash
rtk .venv-eval/bin/python -m tests.eval.realbench.uplift_eval \
  --tag deepseek_free_diagnostic --runner opencode \
  --model opencode/deepseek-v4.1-flash-free --limit 12 --concurrency 1
```

`none/system/gold` 分别用于检查闭卷能力、现行系统注入收益、正确记忆的可用收益。按配对报告，模型与冻结输入由 manifest 锁定。

## 数据

| 层 | 领域 | 记忆 | 情境（查询） | 标注 | 为什么选它 |
|---|---|---|---|---|---|
| 外部知识 | firefox | Mozilla Bugzilla 2025 年以来的已知问题（现象、状态、首条描述） | 之后用户提交的重复报告 | 维护者标注的 `dupe_of`（顺着重复链找到最终原始问题） | 具体项目的具体缺陷，多在模型训练截止之后，模型不可能知道 |
| 外部知识 | legal | LePaRD：联邦判决中被引用的判例段落原文 | 后续判决里的引用语境 | 真实引用关系 | 长尾判例原文，模型记不住，律师靠检索 |
| 外部知识 | biomed | SciFact 的 5183 篇论文摘要 | 专家根据论文引文写的科学论断 | 专家标注的支持或反驳证据 | 具体论文的具体结论 |
| 提醒 | security | MITRE CWE 官方弱点条目 | NVD 2024–2025 年的真实 CVE 描述 | NVD 标注；CWE 官方 ChildOf 父子关系算可接受 | 模型知道 CWE，但面对具体漏洞时未必能想到 |
| 提醒 | theorem | Wikipedia 定理条目摘要 | TheoremQA 教材和考试原题 | 专家标注 | 同上。TheoremQA 自带的定理说明是 GPT-4 生成的，所以弃用 |
| 静默 | — | — | DailyDialog 日常对话的开场句 | 不应触发任何记忆 | 衡量"不该推时不推" |

所有记忆混在同一个库里（约 1 万条），和线上一样。系统必须先认出情境属于哪个领域、对应哪条知识。

另外产出两条**按时间顺序的真实经验流**，用来测自我改进：
- `stream_firefox.json`：按提交时间排列的重复报告；
- `stream_legal.json`：按判决日期排列的引用语境，只取被反复引用的判例段落。

## 防泄漏

- 重复报告正文里提到的 bug 编号（`bug 1234567`、`show_bug.cgi?id=`、`bugzil.la/`）一律抹掉。
- 法律引用语境里的判例引文（`X v. Y, 123 F.3d 456 (…)`）一律抹掉。记忆文本里也不放案名，只保留原文段落和法院、年份，逼系统按法律语义匹配。
- 静态评测集和经验流互不重叠。

## 结果（本地测试台：jina-embeddings-v2-base-zh + bge-reranker-base，只比较同环境下的相对差）

### 经验流：越用越会认吗（prequential，400 条，reveal=0.5）

"熟悉"指这条情境的正确记忆此前在流里出现过。评测全程 Jev 回退 0 次，精排失败 0 次。

| 法律判例流 | 命中率 | 熟悉情境 | 后半程熟悉情境 | Precision |
|---|---|---|---|---|
| 只有 hebbian（现状） | 9.8% | 9.8% | 5.6% | 34.5% |
| + 经验样本 | 23.8% | 25.3% | 22.4% | 62.1% |
| + 经验样本 + 反例经验 | 22.8% | 24.2% | 22.4% | 58.3% |

类比识别 A/B（同一次运行的两组，新选择规则；对照组只问类比题不采用，验证过加题不改变其余判定）：

| 法律判例流 | 命中率 | 熟悉情境 | 后半程熟悉情境 | 新情境 | Precision | 平均注入 |
|---|---|---|---|---|---|---|
| 经验样本（对照） | 24.8% | 26.4% | 24.6% | 11.4% | 62.7% | 0.40 |
| **+ 类比识别**（`CE_EXEMPLAR_ANALOGY=on`） | **44.5%** | **48.0%** | **49.7%** | **15.9%** | **70.4%** | 0.63 |

- 熟悉情境命中率提高到 1.8 倍，后半程翻倍，Precision 同时提高 7.7 个点；两组 Jev 回退、精排失败均为 0。
- 对照组的离线一阶模拟（不计推对后多学到的样本）预估命中 39.2%、Precision 68.6%，实测更高：推对的越多，学到的经验越多，认得越准。

| Firefox 已知问题流 | 命中率 | 熟悉情境 | 后半程熟悉情境 | 首次出现 | Precision |
|---|---|---|---|---|---|
| 只有 hebbian（现状） | 41.5% | 19.4% | 25.5% | 48.2% | 81.0% |
| **+ 经验样本** | **44.5%** | **33.3%** | **35.3%** | 47.9% | **85.2%** |
| + 经验样本 + 反例经验 | 44.0% | 33.3% | 33.3% | 47.2% | 84.2% |

- 只有 hebbian 时，系统不会从"错过"中学习：第一次没认出来的已知问题，后续重复报告也认不出来（Firefox 熟悉情境 19.4%，远低于首次出现的 48.2%）。
- 经验样本在两个真实领域上都有效，熟悉情境命中率分别提高到 2.6 倍和 1.7 倍，Precision 也同时提高。
- 反例经验在两个领域上都没有收益，因此默认关闭（`CE_ANTI_EXEMPLAR=off`）。
- 逐条诊断（Firefox 熟悉情境 93 条）显示，有了经验样本后"没召回"从 33 条降到 10 条（73 条被经验样本认出），瓶颈转移到 Jev 的选择规则（被否决 47 条，其中不少单选题 q≥0.8）。据此新增"单选题高确定性"通道（`CE_JEV_CHOICE_OVERRIDE` / `CE_JEV_RESCUE_Q`）。

新选择规则 + 类比识别 A/B（2026-09-25，同一次运行的两组、各用一份库；新选择阈值为现默认，词面召回关）：

| Firefox 已知问题流 | 命中率 | 熟悉情境 | 后半程熟悉情境 | 首次出现 | Precision | 平均注入 |
|---|---|---|---|---|---|---|
| 经验样本（旧选择规则，上表） | 44.5% | 33.3% | 35.3% | 47.9% | 85.2% | 0.52 |
| 经验样本（新选择规则） | 59.8% | 60.2% | 60.8% | 59.6% | 83.6% | 0.71 |
| **+ 类比识别**（现默认） | **61.3%** | **67.7%** | **70.6%** | 59.3% | 81.9% | 0.75 |

- 新选择规则（单选题高确定性通道 + 留一领域交叉验证选出的阈值）单独就把命中率从 44.5% 提到 59.8%，熟悉情境 33.3% → 60.2%，Precision 只降 1.6 个点。
- 类比通道触发 52 次、认对 43 次（83%），其中 6 次是对照组没推中的；两组结果不同的 16 条里类比组多中 11 条（8 条是熟悉情境），对照组多中 5 条（4 条是新情境，属于学习轨迹分叉的噪声）。Firefox 流新问题多、同模块缺陷容易被认成同一类，Precision 降 1.6 个点；法律判例流上 Precision 反而更高。两组 Jev 回退、精排失败均为 0。

托管检索栈（SiliconFlow bge-m3 + bge-reranker-v2-m3，最终配置：新阈值 + 词面召回）上重做法律判例流 A/B：

| 法律判例流（API 评测台） | 命中率 | 熟悉情境 | 后半程熟悉情境 | 新情境 | Precision | 平均注入 |
|---|---|---|---|---|---|---|
| 经验样本（对照） | 35.5% | 36.5% | 38.6% | 27.3% | 64.8% | 0.55 |
| **+ 类比识别**（现默认） | **43.5%** | **45.2%** | **46.9%** | **29.5%** | **65.9%** | 0.66 |

- 更强的检索让对照组本身从 24.8%（本地）升到 35.5%，类比识别再加 8 个点，Precision 不降；每条 match 延迟中位数 1.9 秒（本地 CPU 模型两组并行时约 23 秒）。三组真实经验流 A/B 都是类比识别更好，因此默认开启（`CE_EXEMPLAR_ANALOGY=on`）。

### 静态：第一次见面能否想起（650 正例 + 60 静默）

| | Recall@6 | Precision | 静默率 | MRR |
|---|---|---|---|---|
| 原逻辑（固定剂量） | 41.5% | 14.3% | 86.7% | 0.373 |
| + Jev（v1 规则） | 38.4% | 82.2% | 100% | 0.395 |
| + Jev + 单选题高确定性通道（离线模拟，精确复现上一行后搜得） | 44.6% | 82.0% | 100% | — |

| 领域（Recall / Precision） | 原逻辑 | + Jev（v1） | + 单选题通道（模拟） |
|---|---|---|---|
| firefox | 50.7% / 10.5% | 52.7% / 96.3% | 66.7% / 96.2% |
| legal | 14.0% / 4.5% | 14.7% / 48.9% | 20.7% / 56.4% |
| biomed | 65.7% / 21.4% | 51.7% / 82.4% | 52.9% / 82.7% |
| security | 22.0% / 18.0% | 23.0% / 78.4% | 25.0% / 67.4% |
| theorem | 47.0% / 34.8% | 45.0% / 91.8% | 53.0% / 91.4% |

- 生物医学的 Recall 下降，最初怀疑是 v1 判定问法（"照做会不会更好"）把**反驳**论断的论文摘要判为"没用"。为此试了判定问法 v2（`CE_JEV_PROMPT=v2`，覆盖"建议 + 知识"）：全量实跑 Recall 44.5% → 48.4%，但 Precision 82.0% → 72.9%，每个领域都掉；生物医学只多收回 3 个点——漏掉的正确摘要大多是单选题选了另一篇同主题论文。默认仍用 v1，对比见 `tests/eval/jev_gate/README.md` 第 2.1 节。
- 35% 的 miss 是首次召回失败（安全 68%、法律 57%），原因是抽象知识和具体情境之间的语义鸿沟。为此新增可选的查询扩写（`CE_QUERY_EXPAND=on`）和词面召回（`CE_LEXICAL_RECALL`，现默认开启）。

- "没召回"从 227 条降到 173 条（少了约四分之一），但多进候选池的正确记忆大多卡在最后一步：Jev 对它们信心不足，精排也常把它们刷掉。词面召回的价值要等更强的判官（自训学生）才能完全兑现。

### 经验识别的上限：过去情境的最近邻

把流里过去的每条情境都当作已学会的经验（上限估计），用 BM25 找与当前情境最像的过去情境，看它对应的记忆是否正确：

| 流 | 熟悉情境 | 最近邻即正确 | 前 10 近邻含正确 |
|---|---|---|---|
| legal | 356 | 68.8% | 93.8% |
| firefox | 93 | 73.1% | 89.2% |

同一判例段落被引用的语境在字面上高度相似，"见过就认得"本身已是很强的信号；而现有系统熟悉情境命中率只有约 30%，差距主要在选择环节。只用相似度门槛时，法律流在"最近邻得分 ≥ 其他记忆最高分的 1.3 倍"时触发 58%、精度 77%；Firefox 流里新问题占多数，最近邻常属于别的缺陷，精度只有 17%–36%。所以经验只负责提名，认不认得出要交给判断。最初试的"近邻经验投票"（某条记忆在最像的 10 条经验里占多数就注入）在法律流的影子数据上精度只有 40%–50%，已删除；改为下面的类比识别。

### 类比识别（离线，只调 Jev）

更进一步：不问"这条抽象记忆对当前请求有没有用"，而问"当前情境和它过去适用过的某个真实情境是不是同一类情况"。过去情境按 0.5 概率学会（与经验流一致），BM25 提名 3 条最像的过去情境（各属不同记忆），Jev 对每条答一道 noul、再在三者和 none 之间做一道单选（`analogy_offline.py`；做法已并入产品：`CE_EXEMPLAR_ANALOGY`，同一次 Jev 调用里加题，实测不改变适用性判定的结果）。

| 规则（取单选最高项） | 法律：触发 / 精度 / 认回熟悉情境 | Firefox：触发 / 精度 / 认回熟悉情境 |
|---|---|---|
| 单选 ≥ 0.7 | 238 / 83.6% / 56.1% | 133 / 37.6% / 53.8% |
| 逐条 ≥ 0.8 | 42 / 85.7% / 10.1% | 22 / 90.9% / 21.5% |
| **单选 ≥ 0.7 且逐条 ≥ 0.6（默认门槛）** | **161 / 88.8% / 40.3%** | **41 / 82.9% / 36.6%** |

法律流里熟悉情境多，单选题就够准；Firefox 流里大多是新问题，Jev 常把"同一模块的另一个缺陷"认成同一类，只看单选题会误认，两道题都要过才稳。对照：现有系统（经验样本 + 适用性判定）熟悉情境命中约 30%（法律）/ 33%（Firefox）。

产品里的提名用经验样本的向量相似度（每条记忆取最像的那条样本，取前 3 条记忆），而不是 BM25。同样的学会顺序下，正确记忆出现在前 3 个提名里的比例：法律 向量 75.5% / BM25 78.9%，Firefox 两者都是 57.0%，差别不大，所以暂不给经验样本另建词面索引。

## 结果（第三方 API 评测台：SiliconFlow bge-m3 + bge-reranker-v2-m3）

本地 CPU 模型跑一轮真实基准约 2 小时。换成 SiliconFlow 托管的检索模型（嵌入 `BAAI/bge-m3`，1024 维；精排 `BAAI/bge-reranker-v2-m3`）并发评测（`run_eval --concurrency 2`）后，建议类评测集约 1 分钟、真实基准约 20 分钟，match 延迟中位数 2.4–2.7 秒（本地 9.5 秒）。Jev 问法（v1）与选择阈值（新默认）不变，只换检索模型；两个评测台的分数只在各自内部比较。

| 配置（新选择阈值） | 真实基准 Recall / Precision / F1 | 没召回 / 精排刷掉 / Jev 否决 | 建议类评测集 Recall / Precision |
|---|---|---|---|
| 本地检索模型（离线复算） | 47.2% / 80.4% / 59.5 | — | 88.0% / 95.9% |
| 本地 + 词面召回（离线复算） | 49.0% / 78.6% / 60.3 | — | — |
| API 检索模型 | 50.1% / 75.8% / 60.4 | 195 / 47 / 93 | 91.0% / 92.6% |
| **API + 词面召回（现默认）** | **51.3% / 75.4% / 61.1** | 170 / 58 / 99 | **95.0% / 92.6%** |
| API + 词面召回，精排换 Qwen3-Reranker-8B | 52.7% / 72.5% / 61.0（静默 98.3%） | 170 / 23 / 125 | 93.0% / 94.0% |

- 更强的精排把"精排刷掉"从本地的 117 条降到 47–58 条，Recall 高 3–4 个点；Precision 低 4–5 个点，主要在法律、安全。把精排门槛从 0.01 提到 0.3 只是在 Recall 和 Precision 之间互换，F1 持平（60.1–60.4），门槛不变。
- 新选择阈值在这个评测台上同样更好：旧阈值离线复算 47.9% / 75.5%。在 API 日志上重做留一领域交叉验证，现行阈值的留出 F1（65.5）高于旧阈值（64.2），也高于每折重新挑的阈值（64.9），说明这组阈值不依赖检索模型。
- 词面召回在两个评测台上都提升 F1（本地 +0.8，API 真实基准 +0.7；建议类评测集 Recall +4 个点、Precision 不变），已改为默认开启。
- Qwen3-Reranker-8B 把"精排刷掉"再降到 23 条，但多进来的候选大多被 Jev 否决（99 → 125），F1 持平，Precision、静默率变差，延迟更高，所以不换。检索已不是主要瓶颈，瓶颈在判定——这正是自训判官要解决的。
- 按注入路径拆错注入（API + 词面召回）：主选 421 条、精度 78%；单选高确定性 18 条、61%；补充 23 条、39%。去掉补充会让 F1 从 61.1 降到约 60.7，规则不改。
