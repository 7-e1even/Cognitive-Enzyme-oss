# 数学、物理记忆标注

当前默认使用 `math_physics.v2.json`，是 agent 对已保存竞赛题的内容审核，不是人工裁决的完整 gold。初筛覆盖数学 `self` 的 89 道、物理 `self_v3` 的 372 道现有题；正例集合不穷尽全部记忆。未运行题和未确认题都不计作召回失败。

v1 及其原报告保留。v2 复审实际子问和完整 rule 后，撤回“已知半径求动量→最短返回时间”“交叉电磁场→重力磁场”的两项强正例归因；薄层毛细近似也改为条件性支持。这不表示这些记忆毫无帮助，而是不能用间接帮助证明 Jev 直接适用性判断错误。具体14条线索的完整 rule 哈希与复审理由见 `case_review.v2.json`。

## 配对的含义

每个 `rules` 项固定记忆库、UUID、版本和完整正文 SHA-256，并列出适用题目的 ID、题面哈希与判断理由。标注依据题面、参考解法和记忆条件；原判断器概率、是否已注入和最终作答对错不作为正确标签。原注入只用于在内容审核后找对应的历史记录。

| `relation` | 含义 |
|---|---|
| `direct` | 对至少一个明确子问提供正确、具体的知识或操作；不等于完整题解 |
| `method_hint` | 可选方法或自检提示，不计作必须命中的具体记忆 |
| `conditional` | 条件、公式或题面不完整，暂不计严格正例 |
| `not_applicable` | 具体模板与题设不符，照用会错用条件 |
| `mixed_content` | 含有用片段，也有已发现的错误断言或冲突指令，不计干净正例 |

同题多条 `direct` 可能互补，也可能是替代解法，不要求同时注入全部条目。漏掉某条适用记忆不等于该题没有获得帮助，更不等于它导致了解题错误。未标记的条目不是负例；当前数据不能用于全题集 precision/recall 或解题增益结论。

`M001`、`P001` 等可读别名分别是固定导出文件中数学、物理记忆的 1 起始行号；UUID 与哈希才是标识。`banks` 固定该行序所依赖的完整文件哈希。`content_warnings` 同时固定出错原文片段、版本与可核对的反例。

## 历史版本与时序

最终库的正确方法可能在题目作答后才学到，也可能由旧版改写而来。`historical_witnesses` 为逐份复核的实际判断器输入，固定题目、记忆 UUID、判定 ID、日志版本与实际交付正文哈希，可把旧版判为具体适用、条件适用、提示、不适用或混合错误。

只有实际交付正文完整等于已审核最终正文，或有精确匹配的旧版本见证时，才直接判断命中/漏选。关键词出现在截断前缀里不构成适用证据。v2 的重点复审另固定整个 rule 的 `delivered_rule_sha256`，防止建议正文相同、触发前提却不同而被混用；旧版仅审阅正文的见证仍按其较窄范围解释。历史正文未留存且后来存在正文修改的，保留 `historical_version_unknown`；不靠最终库倒推。

创建时间晚于判断时间的配对记为 `not_yet_learned`。其中不少正是从本题提炼的方法，不能当成召回失败，也不能当作独立泛化证据。最终库重测还需要单独使用其冻结记忆版本、排除的本题来源与近重复清单；不复用原经验流的判断日志。

`triage` 保存已初筛题目；`question_issues` 保留缺失条件、损坏量词/变量和参考答案冲突。弃权并不代表确定全库没有可用记忆。后续补标应保留旧版本和来源，另建新版本；不能拿原模型选择自动填满未知题。

## 离线复现

从仓库根目录运行：

```bash
rtk .venv-eval/bin/python -m tests.eval.offline.diagnose
rtk .venv-eval/bin/python -m tests.eval.offline.forensics
rtk .venv-eval/bin/python -m pytest tests/eval -q
```

诊断器只用标准库和本地记录，不导入模型或数据库客户端。测试以禁止创建 socket 的方式检查离线端到端复算，并校验未来记忆、旧版不适用、截断、服务错误和重复决策不会被错算成漏召回或漏选。
