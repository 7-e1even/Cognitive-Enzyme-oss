# Jev 适用性判定实验（2026-09-24）

问题：给其他 agent 注入记忆时，能否用 Jev（TypeSafe System One，`jev-1.13.0`）给出的**校准概率**来决定推哪些、推几条，并让"注入 → 反馈 → 学习"的自我改进闭环转得更准更快。

结论：能，而且提升很大。同一条本地真实链路上，Recall 从 68% 到 88%，Precision 从 34% 到 96%，静默率保持 100%，MRR 从 0.49 到 0.84。产品代码已接入（`app/typesafe_client.py`，`app/matching/pipeline.py` 中的 Stage 4.5，`app/core/engine.py` 中按适用性加权的学分），没有 key、超时或出错时，逐位回退到原逻辑。

## 1. 同一条本地真实链路的 A/B（最权威）

条件：真实 `Engine.match` 代码加上本地 PG/Qdrant。模型用本地开源版：embedding 为 `jina-embeddings-v2-base-zh`，精排为 `bge-reranker-base`。线上用的 SiliconFlow key 不在手边，所以绝对值低于 `reports/final`，**只看同环境下的相对差**。报表在 `reports/jevL_*`。

| 配置 | Recall@6 | Precision | 静默率 | MRR | miss 归因 |
|---|---|---|---|---|---|
| 原逻辑（固定剂量） | 68.0% | 33.9% | 100% | 0.486 | 精排误删 17 / 未召回 9 / 剂量截断 6 |
| Jev 精排后判定（判定池 12） | 72.0% | 93.4% | 100% | 0.690 | 精排误删 17 / 未召回 9 / Jev 截断 2 |
| Jev 并行（判定池 12） | 65.0% | 95.4% | 100% | 0.640 | Jev 截断 9（判定池按召回序，漏掉精排高位） |
| Jev 并行（判定池 24） | 70.0% | 98.9% | 100% | 0.685 | Jev 截断 4 |
| Jev 并行（判定池 24）+ 救援 | 85.0% | 95.1% | 90.0% | 0.810 | 精排误删 17→**2** |
| Jev 并行（判定池 24）+ 救援 + 强证据门 | 85.0% | 94.9% | 100% | 0.815 | Jev 截断 4 |
| Jev 精排后判定（并集池 24）+ 救援 + 强证据门 | 86.0% | 95.0% | 100% | 0.820 | Jev 截断 2 / 精排误删 3 |
| 上一行 + GLM 第二判官（`CE_JUDGE_LLM=on`） | 83.0% | 98.2% | 100% | 0.788 | Jev 截断 4 |
| **Jev 精排后判定（并集池 36）+ 救援 + 强证据门（默认）** | **88.0%** | **95.8%** | **100%** | **0.840** | Jev 截断 2 / 精排误删 1 |
| 同上，判定池 50 | 85.0% | 95.0% | 100% | 0.820 | Jev 截断 4（单选 50 选 1，概率被摊薄） |

- **救援**：被精排或 floor 淘汰的候选，只要 Jev 明确判定适用，也可以入选。"具体情境对应抽象原则"的间接匹配正是精排的弱区（精排误删是最大的 miss 桶），Jev 把这 17 条救回了 15 条。
- **精排后判定为默认值**：判定池 = 精排后 floor 的幸存者 + 按召回顺序补足的余量，所以精排排得靠前的候选一定会被判到（被 Jev 截断的从 4 条降到 2 条），代价是串行多等约 0.46s（p50）。用户明确要求准确度优先，所以默认采用这种方式；想省延迟可以设 `CE_JEV_STAGE=parallel`。
- **GLM 第二判官默认关闭**：离线实验里融合在 9 个数字上全部持平或提升，但在真实链路上表现为用 Recall 换 Precision（Recall −3、Precision +3.2、MRR −0.032），重新扫阈值也补不回 Recall（最好只到 84%）。融合会让概率变得不那么极端，从而压低救援和补充。只用 Jev 时 Precision 已经有 95%，对自我改进来说，把对的记忆送到 agent 手里更重要。
- **强证据门**：救援时 30 条静默查询中有 3 条被误推。这 3 条其实是同一条查询"旅行保险怎么选？"重复了 3 次，被推了"决策矩阵"方法论记忆。救援意味着两个判官（精排和 Jev）意见相反，所以要求更强的证据：被淘汰的候选必须 p≥0.9 才能入选。用落盘的 Jev 判定离线复核（模拟器完全复现了实际的 0.850/0.951/0.900）：静默率 90%→100%，Recall 不变。

## 2. 选择策略：是/否题 + 单选题（同一请求，不增加请求数）

逐条独立的是/否题容易把一簇近邻全部判成"有用"。在同一请求里再加一道单选题"哪条最有用，或者都没用"，补上相对比较这一维度，延迟只多约 0.2s。

| 数据集（R / P / 静默） | 只用是/否题 τ=0.6 | **单选主推 + 高 p 补充** | GLM-5.3 列表式判定 τ=0.6 |
|---|---|---|---|
| 自家评测集（困难池） | 0.98 / 0.73 / 0.67 | **0.98 / 0.96 / 0.97** | 0.96 / 0.90 / 0.88 |
| TheoremQA（150） | 0.71 / 0.74 / 0.77 | 0.73 / 0.83 / 0.85 | 0.82 / 0.69 / 0.71 |
| MetaTool（150） | 0.74 / 0.73 / 0.78 | 0.79 / 0.88 / 0.91 | 0.83 / 0.78 / 0.83 |

策略（`_apply_jev_dosage`）：
- **主推**：单选题最高项，要求 q≥0.4 且 p≥0.3；当近重复记忆把单选概率摊薄时，只要 p≥0.9 且未判"都没用"，也主推它。
- **补充**：p≥0.9，且 q ≥ 最高 q 的 10%。
- **critical 放行**：severity 为 critical 且 p≥0.7。
- **静默**：单选题判"都没用"的概率 ≥0.5 时，不做任何补充。
- **单选题高确定性**（真实基准加的）：q≥0.8 时即使 p 低也主推，被精排淘汰的候选 q≥0.9 也可救回——知识类记忆（缺陷、判例、论文）按"照做会不会更好"天然拿不到高 p。

### 2.1 判定问法：v1 / v2 / v3（`CE_JEV_PROMPT`）

- v1（默认）：是/否题和单选题都问"照做会不会把事情做得更好"。
- v2：都问"处理这个情境时 agent 该不该知道这条记忆"，明确把反驳性证据算作相关。
- v3：是/否题用 v1，单选题用 v2（同一次调用里两种问法各答各的，实测互不影响）。

真实多领域基准（710 条，同一候选池，新选择规则；v1 / v3 由两次实跑的 Jev 判定离线组合，模拟器能逐位复现实跑）：

| 问法 | Recall | Precision | F1 | 静默 | firefox | legal | biomed | security | theorem |
|---|---|---|---|---|---|---|---|---|---|
| **v1（默认）** | 44.5% | 82.0% | 57.7 | 100% | 66.0 / 96.1 | 20.7 / 56.4 | 52.9 / 82.7 | 25.0 / 67.4 | 53.0 / 91.4 |
| v2 | 48.4% | 72.9% | 58.2 | 100% | 70.7 / 89.8 | 26.7 / 42.6 | 55.8 / 75.0 | 25.0 / 60.0 | 58.0 / 93.5 |
| v3 | 46.0% | 81.4% | 58.8 | 100% | 66.7 / 95.2 | 23.3 / 57.4 | 52.9 / 82.0 | 25.0 / 66.7 | 58.0 / 92.1 |

建议类评测集（130 条）：v1 87.0 / 95.8 / 100，v2 87.0 / 91.7 / 100，v3 86.0 / 95.8 / 100。

- v2 的是/否题太宽松：一簇主题相近的判例段落都被判"相关"，高 p 补充泛滥，精度在每个领域都掉（法律 56% → 43%）。重标门槛（补充线 0.98）能拉回一部分，但建议类评测集的召回会掉 5 个点。
- 生物医学里 v2 也没收回多少反驳性证据：漏掉的正确摘要大多是 Jev 的单选题选了另一篇同主题论文，不是问法的问题。
- v3 比 v1 略好（F1 +1.1），但差距在噪声量级，默认仍用 v1，v3 保留为可选。

## 3. 公开基准（排除"自家数据"偏差）

候选池 = 字面最相近的 11 个 + 正确答案。`run_public.py` 会自动下载数据。

| | AUC | Top-1 | 字面相似度 Top-1 | ECE |
|---|---|---|---|---|
| TheoremQA（747 题，人工标注所需定理） | 0.962 | 79.1% | 24.1% | 0.029 |
| MetaTool（400 条，199 个工具） | 0.979 | 84.5% | 36.5% | 0.020 |
| 合成奥数（中文 / 英文） | 0.990 / 0.993 | 96.9% / 96.9% | 34% / 41% | 0.034 / 0.035 |

- 公开集按固定阈值取舍时，Recall 只有七八成。抽查发现，多数"错误"是 Jev 选了另一个同样说得通的定理或工具（两个数据集都是每题只标一个答案）。
- **中英文效果几乎一样**：官方所说"中文不如英文"，在这个任务上没有体现。

## 4. 与 LLM（GLM-5.3，关闭思考模式）对比

在相同候选池上，判断质量（AUC）基本打平：0.970 对 0.976、0.978 对 0.969、0.967 对 0.968。但 Jev 延迟约为 GLM 的一半（1.2s 对 2.1–2.4s），按输入计费只有 $0.042/Mtok，输出确定，不存在 JSON 解析失败，这次测试中也没被限流。加上单选题之后，Jev 在三个数据集上都超过了 GLM（§2）。**注入链路用 Jev，冷路径（需要生成文本的环节）继续用 LLM。**

### 4.1 反馈判定（capture 被动评估）不换

被动评估的结论会直接变成学分，判错就会让学习学歪。为此手写了 36 段会话（帮上了、被证明错误、无关各 12 段，每段附 1 条干扰记忆，共 72 个判定点），人工标注真值；会话不由 LLM 生成，以免自我偏差。对照结果（`run_feedback.py`）：

| 判官 | 准确率 | 学分记错 | 漏记 |
|---|---|---|---|
| LLM（capture 现行提示词，GLM-5.3） | 100% | 0 | 0 |
| Jev 三选一 | 98.6% | 1（方向相反） | 0 |
| 两者一致才记 | 98.6% | 0 | 1 |

读长对话、指认证据是 LLM 的强项，现有的 LLM 评估已经足够准，所以**这个环节保留 LLM，不接 Jev**。

## 5. 最终配置与闭环自我改进（RSI）模拟

### 5.1 闭环模拟 v1（`rsi_loop.py --epochs 3 --harmful 0.15 --noise 0.1 --cold 0.25`）

条件：真实 `Engine` 代码，查询按 7:3 切成训练集和测试集，只在训练集上给反馈，形态是 `report_batch`，即"这批记忆有没有帮上忙"。模拟设置为：15% 的记忆建议有误（有害），agent 反馈有 10% 报反，25% 的记忆处于冷启动状态（confidence 0.2，低于 hook 门槛）。

| 组 | Recall（第 0→3 轮） | Precision | 有害暴露率 | 学分方向正确率 | 冷启动恢复 |
|---|---|---|---|---|---|
| 原逻辑 | 46.2% → 46.2% | 25.5% → 27.3% | 32.6% → 27.9% | 约 64% | 0/57 |
| Jev + 适用性学分 | 84.6% → 80.8% | 90.6% → 90.6% | 11.6% → 11.6% | 约 83% | 11/57 |
| Jev（关闭适用性学分） | 84.6% → 80.8% | 87.9% → 90.6% | 11.6% → 11.6% | 约 82% | 11/57 |

- **原逻辑几乎不会自我改进**：每批推 3–4 条，只有一个成败信号，学分有三分之一记错对象（N→1 归因问题）。冷启动记忆永远过不了 hook 门槛，也就永远没有被验证的机会。
- **Jev 让闭环真正转起来**：每批约 1.2 条，学分方向正确率升到 83%；冷启动记忆经由"探索项"被推出、验证、升级。
- 局限：测试集只有 43 条查询（1 条查询约等于 4 个百分点），而且每条记忆只和少数查询相关，测试集里的有害记忆大多没在训练中出现过，所以"学习压制有害记忆"在测试集上看不出来。v2 为此增加了训练集评估（对应"熟悉情境再现"）和记忆级指标（有害压制率、好记忆保留率）。

## 6. 记忆语义去重（巩固流程第 4b 步，`app/learning/dedup.py`）

近重复会摊薄单选概率，也会把学分分散到几条相同的记忆上。现有的 `merge_similar` 要求触发词字面重叠 ≥80%，建议文本按空格分词算重叠（对中文无效），而且只比较同领域的记忆。

标定（`run_dedup.py`）：取语料里向量最近的 60 对，人工标注。只有"合并后不丢任何建议"才算重复；方向相反的谬误对、主题相关但建议不同的都算不重复。结果：重复 19 对、不重复 36 对、边界 5 对（不计分）。

| 判定 | 合并 | 正确 | **误合并** | 找回的重复 |
|---|---|---|---|---|
| 现行 `merge_similar` | 0 | 0 | 0 | 0/19 |
| Jev τ=0.7 | 17 | 17 | **0** | 17/19 |
| **Jev τ=0.8（默认）** | 16 | 16 | **0** | 16/19 |
| Jev τ=0.5 | 20 | 19 | 1 | 19/19 |

端到端实跑（本地真实库，250 条记忆，每条取 3 个向量近邻，共 545 个候选对）：合并 28 对，剩 222 条。其中 17 对在标注集里且全部标为重复；另外 11 对未标注，人工逐条核对也全部是重复（沉没成本中英两版、贝叶斯条件概率、非黑即白、幸存者偏差、决策矩阵、断点调试、幂等键、基础比率、相关不等于因果、缓存空值、权威谬误）。**误合并为 0。** 已知不足：保留的是 confidence 更高那条的建议文本，被吸收那条更具体的细节（例如"相对误差 + Double.compare"）只留在日志快照里。

合并是破坏性操作，所以阈值取保守侧：被吸收记忆的完整快照写进演化日志（`absorbed_snapshot`），便于审计和恢复；两条的反馈证据（触发、成功、误报次数）相加，学习不会从零开始。`CE_DEDUP_JEV=off` 可关闭，`CE_DEDUP_TAU` 可调阈值。
